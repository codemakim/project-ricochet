# 고정 편성 기반 스테이지 진행 설계

## 배경

현재 일반 전투는 6열 그리드에서 고정 템플릿 4종과 절차 생성 스타일 5종을
시드로 섞는다. 적 처치 점수가 페이즈와 보스 출현을 결정하고, 시간·화면 위치·활성
인구 조건을 만족할 때 다음 편성을 만든다. 이 구조는 매 런 모양은 달라지지만 다음
문제가 있다.

- 강한 빌드가 편성을 빠르게 지우면 다음 적을 기다리는 공백이 생긴다.
- 적 밀도와 통로를 런 전체에 걸쳐 의도적으로 설계하기 어렵다.
- 화면 압박, 사격 적 배치, 구슬이 틈을 파고드는 구간을 데이터만 보고 조정하기 어렵다.
- 보스 도달이 편성 소진이 아니라 처치 점수에 묶여 전투 흐름을 예측하기 어렵다.

## 목표

- 일반 전투를 시작부터 보스 직전까지 사람이 작성한 편성 데이터로 제어한다.
- 스테이지를 `문단`, 문단을 여러 `편성`으로 구성해 데이터만 바꿔 전투 리듬을
  조정한다.
- 강한 빌드는 다음 편성과 보스를 빨리 만나고, 약한 빌드는 적이 무한히 쌓이지 않게
  한다.
- 첫 구현에서 3스테이지 × 10편성, 총 30개 편성을 제공한다.
- 기존 6열 그리드, 적 카탈로그, 다칸 적, 급속 진입, 보스·보상 흐름을 재사용한다.
- 플레이어 크기와 피격 판정을 줄여 3갈래 보스 탄 사이를 피할 수 있게 한다.

## 제외 범위

- 신규 적 종류, 보스, 보스 공격 패턴
- 빌드 화력을 실시간 측정하는 동적 난이도
- 네 번째 이후 스테이지와 30개를 넘는 추가 편성
- 전장 선택, 신규 그래픽·VFX·사운드
- 런 중간 저장과 이전 런 저장 데이터 이관

## 전투 콘텐츠 구조

### 계층

각 스테이지는 다음 세 문단을 순서대로 사용한다.

| 문단 | 편성 수 | 역할 |
| --- | ---: | --- |
| 도입 | 3 | 즉시 교전, 통로와 기본 적 조합 소개 |
| 압박 | 4 | 적 중첩, 사격·대형 적 비중 증가 |
| 절정 | 3 | 보스 직전 최고 밀도, 마지막 편성 고정 |

각 스테이지는 정확히 10개의 고유 편성을 소유한다. 한 런에서 10개를 모두 사용하되,
도입·압박 문단 안의 순서와 절정 문단의 마지막을 제외한 순서는 런 시드로 섞는다.
절정의 마지막 편성은 항상 고정한다. 같은 시드에서는 같은 순서가 나오며 다른
시드도 문단 경계를 넘겨 편성을 섞지 않는다.

첫 30개 편성은 밸런스와 제작 흐름을 검증하기 위한 완성 단위다. 이후 편성을 더
추가하면 문단별 후보 중 일부를 시드로 고르는 방식으로 확장할 수 있지만, 이번
구현에는 사용하지 않는 후보나 선택 개수 설정을 미리 만들지 않는다.

### 작성 데이터

`AUTHORED_FORMATIONS`는 TypeScript 상수로 둔다. 각 편성은 다음 정보만 가진다.

- 고유 ID
- 행 수
- 역할 설명용 태그
- 적 종류와 시작 셀 `(column, row)`

적의 가로·세로 점유 칸, 기본 인구 비용, 출연 가능 스테이지는 기존
`ENEMY_CATALOG`에서 읽는다. 편성 데이터에 이를 중복하지 않는다. `fragment`는
분열 결과이므로 직접 배치하지 않는다.

`STAGE_SCRIPTS`는 스테이지별 문단과 편성 ID, 보스 종류를 정의한다. 별도 JSON
파서, 팩토리, 범용 스크립트 언어는 만들지 않는다. 기존 `FormationTemplate`과
그리드 배치 규칙을 확장하거나 같은 데이터 형태로 통합한다.

### 데이터 검증

게임 시작 전 기존 설정 검증 경계에서 다음을 확인한다.

- 편성 ID와 스테이지 ID가 유일하다.
- 스크립트가 가리키는 모든 편성이 존재한다.
- 각 스테이지가 도입 3, 압박 4, 절정 3편성을 가진다.
- 셀이 6열과 선언한 행 범위를 벗어나지 않는다.
- 다칸 적끼리 겹치거나 6열·행 경계를 침범하지 않는다.
- 적이 해당 스테이지와 전장에 출연 가능하다.
- 같은 편성을 한 스테이지에서 중복 참조하지 않는다.
- 절정 문단의 마지막 편성이 명시되어 있다.

잘못된 콘텐츠는 조용히 대체하지 않고 구체적인 편성 ID와 셀을 포함한 오류로
개발 빌드와 테스트에서 즉시 실패시킨다.

## 진행 상태와 편성 해제

`EncounterDirector`는 처치 점수 대신 다음 상태를 가진다.

- 현재 스테이지, 문단, 문단 안 순서
- 시드로 확정된 10개 편성 순서
- 마지막으로 해제한 편성 ID와 그 편성의 최초 인구 비용
- 해제한 편성별 생존 인구 비용
- 다음 편성 대기 및 보스 경고 상태

적은 생성될 때 편성 ID를 갖는다. 분열 적이 둘로 나뉘어도 두 잔체는 부모 편성 ID를
유지하고 기존 인구 비용 보존 규칙을 따른다. 따라서 마지막 편성의 생존 비율은
`현재 생존 인구 비용 / 최초 인구 비용`으로 계산한다.

다음 편성은 마지막으로 해제한 편성의 생존 비율이 `35% 이하`일 때 후보가 된다.
이전 편성의 생존 적은 남아 있어도 된다. 정수 반올림 기준을 따로 두지 않고 이 비율을
직접 비교한다. 후보 편성을 더했을 때 현재 문단의 활성 인구 상한을 넘으면 해제를
기다린다.

첫 편성은 런 또는 보상 후 새 스테이지가 시작될 때 즉시 배치한다. 각 문단의 모든
편성이 해제되어야 다음 문단으로 넘어간다. 마지막 편성이 해제된 뒤 일반 적이 모두
죽으면 보스 경고를 시작한다. 따라서 강한 빌드는 빠르게 보스에 도달하지만 일반 적을
건너뛸 수는 없다.

기존 `bossScore`, `scoreTarget`, `startsAtScore`, 처치 점수 기반 `phaseAt()`과
런타임 절차 편성 생성은 제거한다. 처치 경험치, 보상, 적별 점수 등 전투 진행과
무관한 시스템은 유지한다.

## 화면 밀도와 급속 진입

문단별 중앙 설정은 다음과 같다.

| 문단 | 급속 진입 목표 깊이 | 일반 HP 배율 | 대형·엘리트 HP 배율 |
| --- | ---: | ---: | ---: |
| 도입 | 화면 위에서 30% | 1.0 | 1.0 |
| 압박 | 화면 위에서 40% | 1.6 | 1.4 |
| 절정 | 화면 위에서 50% | 2.1 | 1.8 |

활성 인구 상한은 기존 스테이지 압박 곡선을 그대로 옮긴다.

| 스테이지 | 도입 | 압박 | 절정 |
| --- | ---: | ---: | ---: |
| 1 | 16 | 22 | 26 |
| 2 | 26 | 30 | 30 |
| 3 | 28 | 32 | 34 |

HP 배율은 기존 스테이지 기본 배율과 곱한다. 대형·엘리트 판별은 기존 적 분류를
재사용한다. 개별 편성에는 HP 수치를 넣지 않는다. 적 하강 속도는 현재 `9.6px/s`를
유지한다.

화면에 적이 없으면 다음 편성은 `0.35초` 뒤 급속 진입한다. 적이 남아 있으면 새
편성의 맨 아래가 기존 적 무리의 맨 위보다 한 그리드 간격 위에 오도록 목표 위치를
잡되, 문단 목표 깊이보다 아래로 내리지 않는다. 좌표가 아래로 증가할 때 목표 맨
아래 Y는 `min(문단 목표 Y, 기존 적의 맨 위 Y - 한 셀 높이)`다. 공간이 부족하면
일부 또는 전부가 화면 위에서 급속 진입을 마치고 정상 하강한다. 활성 인구 상한은
항상 우선한다.

급속 진입 중 적은 기존 규칙대로 다음 상태다.

- 구슬·플레이어와 충돌하지 않는다.
- 피해를 받지 않는다.
- 탄환을 쏘지 않는다.

목표 도착 시 영구·임시 구슬과 겹치면 기존 구슬 밀어내기 규칙으로 아래쪽 안전
공간에 배출한 뒤 충돌과 공격을 활성화한다. 진입 중 구슬이 적 무리 안에 갇혀 자동
연타하는 상황을 허용하지 않는다.

## 플레이어 회피 판정

플레이어 시각 크기를 `82px`에서 `72px`, 피해 반경을 `28px`에서 `20px`로
줄인다. 이동 속도, 조준, 구슬 흡수 반경은 유지한다. 현재와 이후의 모든 플레이어
스킨은 같은 시각 기준 크기와 피해 반경을 사용한다.

보스 3갈래 탄의 개수, 속도, 각도는 먼저 유지한다. 플레이어가 두 탄도 사이 중앙을
지날 때 피해를 받지 않는지 검증한 뒤에만 패턴 수치를 추가 조정한다.

## 구현 경계와 삭제 범위

- `stageDefinitions.ts`: 작성 편성, 문단 튜닝, 스테이지 스크립트와 검증 책임
- `EncounterDirector.ts`: 스크립트 순회, 35% 해제, 인구 상한, 보스 연결 책임
- `formationRules.ts`: 작성 셀을 기존 `EnemySpec`으로 변환하는 최소 지오메트리만 유지
- `EnemyManager.ts`: 편성 ID 생존 인구 보고와 기존 급속 진입 처리
- `gameTuning.ts`: 공통 35%, 0.35초, 플레이어 크기·피격 반경 같은 전역 수치

`createInitialFormation()`, `createReinforcementFormation()`과 런타임에서 쓰지 않는
절차 스타일·가중치·프로필 코드는 마이그레이션 뒤 삭제한다. 격자 점유, 다칸 적,
셀 경계·겹침 검증, 시드 셔플, HP 계산 같은 재사용 가능한 규칙은 유지한다. 기존
`reservedPassageCells()`는 런타임 절차 생성과 함께 삭제한다. 고정 편성의 빈 셀이
곧 의도한 통로다. 호환용 이중 실행이나 예전 생성기로의 폴백은 두지 않는다.

개발자 스냅샷에는 스테이지, 문단, 문단 내 편성 번호, 편성 ID, 마지막 편성 생존
비율, 활성 인구와 상한을 표시한다. 제거된 보스 점수와 페이즈 점수는 표시하지 않는다.

## 전환 순서

1. 기존 타입과 검증을 재사용해 작성 편성 30개와 3개 스테이지 스크립트를 추가한다.
2. 작성 편성을 `EnemySpec`으로 변환하고 편성 ID를 적 생명주기에 보존한다.
3. `EncounterDirector`를 스크립트 순회와 35% 해제 규칙으로 교체한다.
4. 급속 진입 목표 깊이와 문단별 HP 배율을 연결한다.
5. 보스 점수 게이트와 런타임 절차 생성 코드를 삭제한다.
6. 플레이어 크기와 피해 반경을 조정한다.
7. 집중 테스트 뒤 전체 단위 테스트, 빌드, Chromium E2E를 한 번씩 실행한다.

각 단계에서 기존 일반 전투 경로를 따로 유지하지 않는다. 새 경로가 준비되는 같은
변경 안에서 호출자를 옮기고 죽은 코드를 제거한다.

## 검증

### 단위 테스트

- 같은 시드는 같은 문단 내 순서를 만들고, 다른 시드도 허용된 문단 밖으로 섞지 않는다.
- 각 스테이지가 10개 편성을 중복·누락 없이 해제한다.
- 마지막 편성 생존 비율이 35%를 초과하면 대기하고 35% 이하면 다음 편성을 후보로 삼는다.
- 35%를 만족해도 활성 인구 상한을 넘으면 대기한다.
- 분열 뒤 잔체의 편성 ID와 인구 비용이 보존된다.
- 빈 화면은 0.35초 뒤, 비어 있지 않은 화면은 기존 적 위 목표로 급속 진입한다.
- 급속 진입 중 충돌·피해·사격이 없고 도착 때 겹친 구슬이 배출된다.
- 도입·압박·절정의 목표 깊이와 HP 배율이 정확히 적용된다.
- 10번째 편성 해제만으로 보스가 나오지 않고 남은 일반 적이 모두 죽은 뒤 경고한다.
- 보스 보상 후 다음 스테이지의 첫 편성이 즉시 시작된다.
- 플레이어 시각 크기 72px와 피해 반경 20px를 고정한다.

### 브라우저 검증

- 첫 보스 전까지 적이 없는 시간이 5초를 넘지 않는다.
- 압박·절정 문단에서 강한 3구슬 빌드도 다음 편성이 끊기지 않고 화면에 쌓인다.
- 편성 사이에 구슬이 파고들 통로와 밀집 구간이 모두 나타난다.
- 급속 진입 적을 화면 밖 구슬이 미리 때리거나 적 안에서 연타하지 않는다.
- 세 스테이지에서 편성 10개 뒤 기존 보스·보상·다음 스테이지 흐름이 이어진다.
- 플레이어가 1보스 3갈래 탄 사이를 실제 이동해 피할 수 있다.

완료 판정은 관련 집중 테스트, 전체 단위 테스트, 프로덕션 빌드, Chromium E2E 통과와
위 브라우저 항목의 실제 구동 확인을 모두 요구한다.
