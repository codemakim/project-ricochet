# Project Ricochet 구슬 발견·도감 설계

## 1. 목표

런에서 처음 획득한 기본 구슬과 처음 생성한 융합 구슬을 영구 발견 기록으로 남긴다. 미발견 구슬은 전투 보상과 작업장에서 정체를 감추고, 발견한 기본 구슬만 부품으로 시작 구슬 해금이 가능하게 한다.

이번 작업은 반복 플레이 목표를 추가하는 메타 진행 작업이다. 구슬 전투 효과와 밸런스 수치는 바꾸지 않는다.

## 2. 저장 규칙

`MetaProgress`를 스키마 3으로 올리고 아래 목록을 추가한다.

- `discoveredCores: OrbCoreId[]`
- `discoveredFusions: FusionOrbId[]`

새 저장의 기본 발견 목록은 시작 구슬인 `echo` 하나다. 스키마 1·2 저장은 기존 `unlockedCores` 전체를 발견한 기본 구슬로 이관하고 융합 발견 목록은 빈 배열로 시작한다. 이미 해금한 구슬이 마이그레이션 뒤 가려지거나 장착 불가능해지지 않아야 한다.

저장은 런 종료 시점에만 수행한다. 승리와 사망 모두 `RunResult`를 정산하면서 이번 런의 발견 목록을 기존 목록에 합친다. 중복 ID는 한 번만 보존한다. 브라우저 새로고침이나 강제 종료로 정산되지 않은 런의 발견은 저장하지 않는다.

저장소는 기본·융합 ID를 각각 등록된 목록으로 검증한다. 알 수 없는 ID나 잘못된 배열은 기존 손상 저장 처리 규칙을 따른다.

## 3. 런 데이터 흐름

`RunConfig`는 영구 `discoveredCoreTypes`와 `discoveredFusionTypes`를 `CombatScene`에 전달한다. 전투는 두 목록을 복사한 런 로컬 발견 집합을 가진다.

- 시작 구슬은 이미 발견한 구슬만 장착 가능하므로 추가 발견을 만들지 않는다.
- 기본 구슬 획득이 확정되면 해당 종류를 런 로컬 집합에 추가한다.
- 융합 재료 선택과 생성이 성공하면 해당 융합 종류를 런 로컬 집합에 추가한다.
- 발견 직후부터 같은 런의 이후 카드와 설명에서는 실제 이름과 효과를 표시한다.
- 취소되거나 실패한 보상 선택은 발견을 만들지 않는다.

런 종료 시 `RunResult`는 최종 기본·융합 발견 목록을 반환한다. `settleRun()`은 보상 부품과 별개로 발견 목록을 합친다. 같은 `runId`를 다시 정산하는 경우 기존 중복 정산 방지 규칙을 유지하며 새 기록도 적용하지 않는다.

## 4. 전투 표시

기존 보상 UI 구조를 유지하고 표시 문자열만 발견 상태에 따라 바꾼다.

### 4.1 기본 구슬

미발견 기본 구슬 카드는 다음만 보여준다.

- 이름: `???`
- 기존 색과 실루엣
- `직격형`, `분열형` 같은 짧은 역할 힌트

정확한 효과, 레벨별 변화와 실제 이름은 숨긴다. 획득 확정 뒤 즉시 공개한다.

### 4.2 융합 구슬

미발견 융합 카드는 `??? 융합`, 필요한 두 재료와 역할 힌트를 보여준다. 결과 이름과 상세 효과는 숨긴다. 재료 선택 화면에서도 확정 전 결과 이름을 가리고 결과 레벨과 소비 재료는 보여준다. 융합 성공 뒤 즉시 실제 이름과 효과를 공개한다.

각 기본·융합 정의에 플레이어용 `roleHint` 한 줄을 둔다. 별도 설명 레지스트리는 만들지 않는다.

## 5. 작업장과 해금

기존 코어 작업장을 한 화면의 두 구역으로 확장한다.

### 5.1 기본 구슬

- 미발견: `???`, 역할 힌트, `미발견`; 구매 버튼 없음
- 발견·미해금: 이름, 요약, 가격, 구매 버튼
- 해금: 이름, 요약, `해금됨`

`purchaseCore()`는 발견하지 않은 기본 구슬 구매를 거부한다. 가격 순서는 현재 `unlockedCores.length` 기반 규칙을 유지한다. 구매한 기본 구슬만 출격 화면의 시작 구슬 선택지에 나온다.

### 5.2 융합 기록

현재 실제 구현된 광자 궤도, 공명 군체, 나노 증식체만 표시한다.

- 미발견: `???`, 역할 힌트, 재료 이름은 표시
- 발견: 이름, 요약, 재료 조합 표시

융합에는 구매나 별도 재화 해금이 없다. 아직 구현하지 않은 나머지 6종과 초월 합성은 표시하지 않는다.

## 6. 구성 요소 변경

- `metaProgress`: 발견 목록 기본값, 정산 합집합, 미발견 구매 차단
- `MetaStore`: 스키마 3 검증과 스키마 1·2 마이그레이션
- `runContract`: 영구 발견 입력과 런 종료 발견 출력
- `CombatScene`: 런 로컬 발견 집합과 성공한 획득·융합 기록
- `LevelUpOverlay`, `OrbFusionOverlay`: 발견 여부 기반 마스킹
- `AppController`: 발견 목록 전달과 작업장 두 구역 렌더링
- 기본·융합 정의: 짧은 `roleHint`

새 Scene, 저장소, UI 프레임워크, 범용 도감 엔진은 추가하지 않는다.

## 7. 오류와 경계 조건

- 기존 해금 구슬은 마이그레이션 시 반드시 발견 처리한다.
- 미발견 구슬 구매는 UI와 순수 규칙 양쪽에서 차단한다.
- 실패한 융합, 취소된 선택, 단순 카드 노출은 발견으로 기록하지 않는다.
- 같은 종류의 물리 구슬을 여러 개 얻어도 발견 목록은 중복되지 않는다.
- 등록되지 않은 기본·융합 ID가 저장에 있으면 손상 저장으로 처리한다.
- 발견 상태는 전투 효과, 출현 확률과 보상 카드 구성에 영향을 주지 않는다.

## 8. 검증

단위 테스트로 다음을 검증한다.

- 스키마 1·2에서 3으로의 마이그레이션
- 새 저장의 기본 발견 목록
- 승리·사망 정산의 발견 합집합과 중복 방지
- 중복 `runId` 정산 차단
- 미발견 구매 거부와 발견 후 구매
- 기본·융합 카드 마스킹
- 획득·융합 성공 뒤 런 중 즉시 공개
- 잘못된 발견 ID 저장 거부

브라우저 테스트는 데스크톱 한 경로에서 미발견 기본 구슬 획득, 런 종료 저장, 작업장 공개와 구매 가능 상태를 검증한다. 모바일 입력은 기존 보상 선택 회귀 테스트로 유지한다.

## 9. 제외 범위

- 첫 3종 융합 밸런스 조정
- 나머지 6종 융합
- 초월 합성
- 도감 전용 Scene과 상세 통계
- 발견 연출, 실제 아트와 사운드
- 전투 중 즉시 영구 저장
