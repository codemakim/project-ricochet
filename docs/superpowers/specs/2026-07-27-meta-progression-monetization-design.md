# Project Ricochet 외부 루프·메타 진행·수익 모델 설계

## 1. 목적

이 문서는 한 번의 전투 밖에서 플레이어가 무엇을 선택하고, 무엇을 얻고, 왜 다음 런을 시작하는지 정의한다. 메뉴, 출격 준비, 결과, 무료 재화, 영구 해금, 고정 위협도, 광고와 유료 상품을 하나의 제품 흐름으로 묶는다.

전투와 런 내부 빌드는 다음 문서를 따른다.

- `2026-07-13-project-ricochet-core-redesign.md`
- `2026-07-24-stage-engine-hive-enrage-design.md`
- `2026-07-27-run-build-system-redesign.md`

이 문서는 위 설계를 대체하지 않는다. 전투 전후의 외부 루프만 소유한다.

## 2. 목표

- 에너지 제한 없이 원하는 만큼 플레이할 수 있다.
- 실패한 런도 작은 영구 진척을 남긴다.
- 영구 성장으로 조작과 전투 밸런스를 무너뜨리지 않는다.
- 새 구슬과 능력 해금이 다음 런의 빌드 가능성을 넓힌다.
- 모든 해금은 결정적이며 유료 랜덤 상품을 사용하지 않는다.
- 한 전장을 여러 위협도로 반복할 이유가 있다.
- 광고는 런 사이에만 나타나며 짧은 실패와 온보딩을 방해하지 않는다.
- 유료 확장팩은 배경 교체가 아니라 새로운 물리 규칙과 전투 경험을 제공한다.
- 첫 구현은 한 사이클을 완성하고 일일 미션, 무한 모드, 온라인 순위표는 만들지 않는다.

## 3. 제품 모델

### 3.1 기본 배포

- 모바일 앱은 무료로 내려받는다.
- 기본 전장은 제한 없이 플레이할 수 있다.
- 에너지, 입장권, 대기 시간은 없다.
- 정상적인 런 사이에 전면 광고를 표시한다.
- 영구 광고 제거, 직접 판매 스킨, 전장 확장팩으로 수익을 낸다.
- PC판을 출시하면 광고 없는 유료 완제품으로 구성한다.

### 3.2 판매하지 않는 것

- 무료 재화 `부품`
- 영구 공격력
- 구슬 속도와 발동 확률
- 부활권
- 광고 보상으로 얻는 전투 능력
- 랜덤 구슬·능력·스킨 상자
- 프리미엄 재화
- 에너지와 플레이 시간

현금 결제는 플레이 시간을 단축하거나 전투 수치를 높이지 않는다.

## 4. 전체 플레이 흐름

```text
앱 시작
→ 저장 데이터와 구매 권한 확인
→ 출격 탭
→ 전장·위협도·영구 구슬 구성 확인
→ 런 시작
→ 클리어 또는 실패
→ 결과와 부품·해금 진행 표시
→ 계속
→ 광고 조건 판정
→ 출격 탭
→ 작업장에서 연구 또는 즉시 재출격
```

전장 하나는 일반 구간과 필수 보스 3개로 구성하며 목표 런 시간은 10~15분이다. 마지막 보스 보상 선택 뒤 전장이 끝나고 결과 화면으로 이동한다.

## 5. 메뉴 구조

하단 고정 탭 4개와 우측 상단 설정 버튼을 사용한다. 별도의 장식용 허브 장면은 만들지 않는다.

### 5.1 출격

- 선택한 전장
- 선택한 위협도
- 영구 구슬 3개 구성
- 해당 조합의 최고 기록
- 잠긴 콘텐츠의 해금 조건
- 출격 버튼

앱 시작과 런 종료 후 기본 진입 탭이다. 마지막 유효 구성을 기억한다. 구성에 잠긴 구슬이 포함되거나 전장이 유효하지 않으면 기본 구성으로 복구하고 이유를 한 번 표시한다.

### 5.2 작업장

작업장 안에서 화면만 전환한다.

- `코어`: 영구 구슬 종류 해금과 시작 구슬 3개 구성
- `연구`: 일반 능력 해금과 런 내 최대 등급 개방
- `정비`: 제한된 영구 능력치
- `외형`: 로봇, 구슬, 색상, 궤적, 충돌 효과

해금되지 않은 항목도 이름, 성능, 비용과 조건을 표시한다. 숨겨진 랜덤 연구는 없다.

### 5.3 기록

- 전장별 최고 위협도
- 전장·위협도별 최고 점수와 최단 클리어 시간
- 최근 클리어 빌드
- 영구 구슬, 일반 능력, 적과 보스 도감
- 고정 도전 과제와 보상

온라인 순위표와 다른 사용자의 기록은 첫 구현 범위가 아니다.

### 5.4 상점

- 영구 광고 제거 팩
- 직접 판매 스킨과 이펙트 팩
- 전장 확장팩
- 구매 복원

각 상품은 실제 현금 가격을 직접 표시한다. 프리미엄 재화로 가격을 가리지 않는다.

### 5.5 설정

- 배경음·효과음 음량
- 진동
- 화면 흔들림과 강한 섬광 감소
- 조준선 표시
- 조작 감도
- 개인정보·오픈소스 고지
- 저장 데이터 초기화

저장 초기화는 확인을 두 번 받고 구매 권한은 삭제하지 않는다.

## 6. 출격 준비

### 6.1 전장과 위협도

- 처음에는 기본 전장과 위협도 0만 선택할 수 있다.
- 현재 위협도를 클리어하면 같은 전장의 다음 고정 위협도가 열린다.
- 잠긴 위협도는 필요한 이전 클리어 조건을 표시한다.
- 유료 전장은 구매 권한이 있어야 선택할 수 있다.
- 유료 전장도 첫 위협도부터 순서대로 진행한다.

### 6.2 시작 영구 구슬

- 처음에는 `반향 코어`만 해금한다.
- 시작 영구 구슬 3개는 모두 해금된 종류 안에서 자유롭게 선택한다.
- 같은 종류를 중복 선택할 수 있다.
- 첫 런 결과로 다른 코어 하나를 선택 해금할 수 있을 만큼 부품을 얻는다.
- 전도, 부식, 관성 코어 중 어느 것을 먼저 살지는 플레이어가 정한다.

### 6.3 시작 능력 풀

다음 12종은 처음부터 런의 레벨업 풀에 들어간다.

1. 화력 증폭
2. 운동 에너지
3. 추가 코어
4. 코어 팽창
5. 흡수장 확장
6. 장갑 보강
7. 근접 증폭
8. 정밀 직격
9. 재장전 과충전
10. 벽 가속
11. 충격 폭발
12. 분열 프로토콜

나머지 일반 능력은 작업장에서 해금하면 이후 모든 런의 선택지 풀에 자동 편입된다.

## 7. 무료 재화 `부품`

### 7.1 원칙

- 부품은 플레이로만 얻는다.
- 현금 구매와 광고 시청으로 얻을 수 없다.
- 런에서 얻은 부품은 결과 확정 시 저장한다.
- 앱이 결과 화면에서 종료돼도 완료된 전투 보상은 중복 없이 한 번 지급한다.
- 일반 적 처치 수와 무한 비례하지 않는다.

### 7.2 런 보상

초기 튜닝 값은 다음과 같다.

| 조건 | 부품 |
|---|---:|
| 3분 이상 런 참여 | 10 |
| 첫 유효 런 완료 추가 | 30 |
| 첫 번째 보스 반복 처치 | 12 |
| 두 번째 보스 반복 처치 | 18 |
| 세 번째 보스 반복 처치 | 25 |
| 전장 클리어 | 30 |
| 각 보스 최초 처치 추가 | 20 |
| 위협도 최초 클리어 추가 | 60 |
| 고정 도전 과제 | 20~60 |

- 3분 미만 포기에는 참여 보상이 없다.
- 3분 전에 보스를 처치하면 보스 보상은 정상 지급한다.
- `첫 유효 런`은 3분 이상 진행했거나 보스를 하나 이상 처치한 첫 런이다.
- 첫 유효 런은 참여 보상과 최초 완료 추가 보상으로 최소 40부품을 지급한다.
- 런 실패 시에도 이미 처치한 보스 보상은 유지한다.
- 돌파 피해나 게임 오버 뒤 추가 보상을 계산하지 않는다.
- 같은 최초 보상은 저장된 claim ID로 한 번만 지급한다.

위 값은 `META_TUNING` 한곳에 둔다. 핵심 해금의 목표 속도를 바꿀 때 코드가 아니라 값만 조정한다.

### 7.3 목표 속도

- 첫 런 결과: 새 영구 구슬 1종 선택 가능
- 12~20런: 영구 구슬 4종과 일반 능력 대부분 해금
- 이후: 일반 능력 최대 등급, 영구 능력치와 무료 외형 완성

한 전장을 반복해야 하므로 초기 핵심 해금에 30런 이상을 요구하지 않는다.

## 8. 연구와 해금

### 8.1 영구 구슬

반향 코어는 무료다. 나머지 코어 가격은 종류가 아니라 구매 순서에 따른다.

| 추가 해금 순서 | 부품 |
|---:|---:|
| 첫 번째 | 40 |
| 두 번째 | 100 |
| 세 번째 | 160 |

플레이어는 세 코어 중 원하는 것을 각 가격 단계에서 선택한다.

### 8.2 일반 능력

- 기본 12종은 무료로 해금된다.
- 추가 능력의 기본 해금 가격은 소형 수치 능력 `25`, 조건형 능력 `35`, 새 발동 효과 `50`이다.
- 능력 해금 시 설계 최대 등급이 2 이상이면 런 내 2등급까지 사용할 수 있다.
- 최대 등급 1인 능력은 해금과 동시에 완성된다.
- 선행 효과가 필요한 조정 능력은 원본 효과 해금 뒤 구매할 수 있다.
- 구매 전에 선행 조건과 최종 최대 등급을 표시한다.

### 8.3 런 내 최대 등급 개방

| 새 최대 등급 | 부품 |
|---:|---:|
| 3등급 | 25 |
| 4등급 | 40 |
| 5등급 | 60 |

- 능력 사용 횟수, 처치 수, 숙련도는 요구하지 않는다.
- 설계 최대 등급을 넘길 수 없다.
- 최대 등급 개방은 다음 런부터 적용한다.
- 이미 진행 중인 런의 선택지와 등급 상한은 바꾸지 않는다.

### 8.4 제한된 영구 능력치

| 연구 | 효과 | 단계별 비용 |
|---|---|---|
| 장갑 보정 | 최대 체력 `+1`, 최대 3단계 | `40 / 80 / 140` |
| 기동 보정 | 이동 속도 `+3%`, 최대 3단계 | `35 / 70 / 120` |
| 흡수장 보정 | 회수 반경 `+4px`, 최대 3단계 | `30 / 60 / 100` |
| 응급 정비 키트 | 런당 1회, 체력이 3 이하가 되면 자동으로 2 회복 | `120` |

- 공격력, 구슬 속도와 발동 확률의 영구 연구는 없다.
- 응급 정비 키트는 피해 처리와 사망 확정 사이에 한 번만 발동한다.
- 한 번의 피해가 회복 후에도 체력을 0 이하로 만들면 사망한다.
- 새 런에서 정비 키트 사용 상태를 초기화한다.

### 8.5 외형

- 일부 기본 색상, 궤적과 이펙트는 부품으로 해금한다.
- 도전 과제 전용 외형은 부품으로 대신 살 수 없다.
- 유료 스킨은 성능과 hitbox를 바꾸지 않는다.
- 같은 로봇과 구슬의 외형 차이는 색만 바꾸지 않고 실루엣, 발광부와 궤적을 함께 바꾼다.

## 9. 결과 화면

결과 화면은 다음 순서로 정보를 표시한다.

1. `클리어` 또는 `작전 실패`
2. 도달 보스와 전투 시간
3. 이번 런 빌드와 영구 구슬 구성
4. 참여, 보스, 클리어와 최초 보상의 부품 명세
5. 새 해금 가능 항목
6. 기록 갱신
7. `계속` 버튼

결과는 화면이 열린 시점에 한 번 계산하고 claim record를 먼저 저장한 뒤 잔액에 반영한다. 저장 도중 앱이 종료돼도 같은 run ID를 다시 정산하지 않는다.

첫 런 결과에서는 새 코어를 살 수 있다는 안내와 작업장 바로가기 버튼을 강조한다. 구매를 강제하지 않으며 즉시 재출격도 가능하다.

## 10. 고정 위협도

### 10.1 규칙

- 전장별 위협도는 데이터 목록으로 정의한다.
- 위협도 0을 클리어하면 1, 1을 클리어하면 2가 열린다.
- 첫 완성 사이클은 위협도 0만 콘텐츠로 제공한다.
- 후속 고정 위협도는 같은 실행 구조에 데이터로 추가한다.
- 난도는 적 하강 속도보다 적 수, HP, 특수 적 비율, 탄환 패턴과 보스 기술로 올린다.
- 각 위협도는 최초 클리어 보상과 기록을 독립적으로 가진다.

### 10.2 후속 모드용 최소 데이터

첫 구현에서 일일 도전과 무한 과부하는 만들지 않는다. 다음 값만 모든 런에 보존한다.

```ts
interface RunIdentity {
  runId: string;
  battlefieldId: string;
  threatId: string;
  seed: number;
}
```

위협도 정의는 배열 데이터이며 메뉴는 해금된 항목을 그 목록에서 읽는다. 새 모드 관리자, 범용 modifier DSL과 서버 API는 만들지 않는다.

### 10.3 기본 고정 도전

고정 도전은 별도 게임 모드가 아니라 일반 런 결과에서 한 번 판정하는 업적이다.

| 도전 | 조건 | 부품 |
|---|---|---:|
| 단일 공명 | 반향 코어 3개로 위협도 0 클리어 | 30 |
| 혼성 회로 | 서로 다른 코어 3개로 클리어 | 40 |
| 무결점 격파 | 한 보스전 동안 피해 없이 해당 보스 처치 | 보스당 20 |
| 정비 불필요 | 응급 정비 키트가 발동하지 않고 클리어 | 40 |
| 신속 진압 | 12분 안에 클리어 | 50 |
| 순수 직격 | 폭발, 분열, 레이저와 가스 없이 클리어 | 60 |

- 각 도전은 계정당 한 번 보상을 지급한다.
- 아직 해금하지 않은 코어나 능력을 요구하는 도전도 기록 탭에서 조건을 미리 볼 수 있다.
- 일일 초기화와 기간 제한은 없다.
- 도전 판정은 저장된 `RunResult`만 사용하며 전투 코드에 업적별 분기를 넣지 않는다.

## 11. 광고

### 11.1 표시 조건

전면 광고는 다음 조건을 모두 만족할 때만 요청한다.

- 광고 제거 권한이 없음
- 유효 런 완료 수가 2회 초과
- 현재 런이 3분 이상 지속됐거나 보스를 하나 이상 처치
- 마지막 전면 광고 뒤 gameplay 기준 10분 이상 경과
- 결과 화면에서 플레이어가 `계속`을 누름

광고는 결과 보상을 가리지 않는다. 결과를 본 뒤 출격 탭으로 돌아가기 전에 표시한다.

### 11.2 실패 처리

- 광고 재고 없음, 네트워크 실패, SDK 오류면 즉시 출격 탭으로 이동한다.
- 광고 실패를 재시도하거나 플레이를 막지 않는다.
- 앱이 배경으로 갔다 돌아와도 같은 결과에서 광고를 두 번 요청하지 않는다.
- 광고 시청 여부는 보상과 관계없다.
- 튜토리얼, 설정 테스트와 개발 빌드에는 실제 광고를 표시하지 않는다.

### 11.3 광고 제거

광고 제거는 영구 비소모성 구매다.

```text
adFree =
  광고 제거 팩 보유
  또는 전장 확장팩을 하나 이상 보유
  또는 광고 없는 PC 배포판
```

- 스킨만 구매한 경우 광고 제거 권한은 생기지 않는다.
- 광고 제거 팩에는 후원자 전용 외형 1세트를 포함할 수 있다.
- 월 광고 제거와 구독 상품은 없다.

## 12. 유료 상품

### 12.1 영구 광고 제거 팩

- 모든 전면 광고 영구 제거
- 선택형 후원자 외형 1세트
- 전투 수치 없음

### 12.2 스킨과 이펙트 팩

- 로봇 본체
- 영구 구슬 외형
- 궤적
- 충돌, 폭발과 레이저 표현

직접 구매만 제공한다. 랜덤 상자와 기간 한정 압박은 사용하지 않는다.

아트는 Project Ricochet 전용 원화와 게임용 리소스로 제작한다. 이미지 생성은 콘셉트와 원본 제작에 사용할 수 있지만 최종 hitbox, 투명 배경, 프레임 일관성, 색 구분과 게임 내 가독성은 직접 검수한다.

### 12.3 전장 확장팩

확장팩 하나는 다음을 제공한다.

- 전장 1개
- 일반 구간과 필수 보스 3개
- 전용 적 조합
- 전용 환경 규칙
- 고정 위협도
- 도전 과제와 외형
- 필요하면 옆 방향 성능의 구슬 또는 능력
- 영구 광고 제거 권한

확장 전용 구슬과 능력은 기본 전장을 클리어하는 데 필요하지 않으며 기존 항목의 상위 호환으로 만들지 않는다.

#### 핀볼 전장 방향

- 자동 범퍼
- 속도 증폭 레일
- 구슬로 켜는 스위치
- 스위치에 반응하는 플리퍼형 반사벽
- 한 방향 게이트

이동·조준·회수 조작은 유지한다. 별도 플리퍼 버튼은 추가하지 않는다.

#### 당구 전장 방향

- 쿠션 각도를 바꾸는 지형
- 충돌로 서로 밀리는 적
- 포켓형 위험 구역
- 연쇄 충돌 목표
- 보스가 배치하는 임시 공과 장애물

핀볼과 당구 전장의 세부 전투 규칙은 실제 제작 전에 각각 별도 설계한다.

## 13. 구매 권한과 저장

### 13.1 로컬 진행 저장

브라우저 로컬 저장에는 다음을 보존한다.

- schema version
- 부품 잔액과 claim record
- 영구 구슬·능력·최대 등급 해금
- 영구 능력치
- 외형 선택
- 전장·위협도 클리어
- 도전 과제
- 기록과 최근 빌드
- 광고 횟수와 마지막 광고 gameplay 시간
- 마지막 출격 구성
- 설정

저장은 한 객체로 versioning하며 알 수 없는 필드는 무시한다. 마이그레이션에 실패하면 원본을 별도 백업하고 기본값으로 시작할지 사용자에게 확인한다.

### 13.2 구매 권한

- 모바일 구매 권한은 플랫폼 영수증을 기준으로 복원한다.
- 로컬 저장 초기화로 구매 권한을 지우지 않는다.
- 이전에 확인한 구매는 오프라인에서도 캐시된 권한을 사용한다.
- 구매 실패와 취소는 진행 저장을 바꾸지 않는다.
- 구매 완료 뒤 권한 적용이 실패하면 다음 앱 시작과 `구매 복원`에서 다시 확인한다.

첫 웹 수직 구현에는 실제 광고·결제 SDK를 넣지 않는다. 모바일 패키징 작업에서 플랫폼 결제와 광고를 연결한다. 웹 수직 구현은 광고 제거와 상품 구매 상태를 개발 설정으로만 검증한다.

기본 전장의 완전한 10~15분 사이클에는 필수 보스 3개가 필요하다. 현재 존재하는 두 보스 뒤에 들어갈 세 번째 보스는 별도 전투 콘텐츠 설계와 구현을 거친다. 외부 루프는 보스 수를 하드코딩하지 않고 현재 `StageDefinition`에 등록된 필수 보스 결과를 정산한다.

## 14. 구조

첫 사이클에 필요한 경계만 둔다.

### 14.1 `MetaProgress`

- 부품 잔액
- 해금된 코어와 능력
- 능력별 최대 등급
- 영구 능력치
- 전장·위협도 진행
- 도전과 기록

전투 객체를 알지 않으며 저장 가능한 순수 데이터다.

### 14.2 `RunResult`

- `RunIdentity`
- 성공 여부
- 지속 시간
- 처치한 보스 ID
- 빌드와 구슬 구성
- 기록 값

결과 보상 계산은 `RunResult`와 기존 claim 목록을 입력으로 받는 순수 함수다.

### 14.3 `Entitlements`

- 광고 제거
- 구매한 스킨 팩
- 구매한 전장 확장팩

첫 웹 수직 구현에서는 저장 가능한 개발 값이다. 실제 모바일 결제 연결 시 플랫폼 결과로 교체한다. 전투와 부품 계산은 구매 API를 직접 호출하지 않는다.

### 14.4 UI

기존 HTML UI 방식을 재사용한다. 메뉴 프레임워크와 별도 라우터를 추가하지 않는다.

- 현재 탭 ID
- 작업장 하위 화면 ID
- 출격 구성
- 결과 overlay

전투가 시작되면 메뉴 DOM을 숨기고 기존 `CombatScene`을 사용한다. 런 종료 시 전투 객체를 정리한 뒤 결과 overlay를 표시한다.

### 14.5 중앙 설정

`META_TUNING`에는 다음만 둔다.

- 부품 보상
- 해금과 연구 비용
- 광고 면제 런 수
- 광고 최소 간격
- 짧은 런 기준
- 영구 능력치 단계 값

상품 가격과 스토어 상품 ID는 플랫폼 배포 설정에 둔다. 게임플레이 코드에 현금 가격을 넣지 않는다.

## 15. 오류와 경계 조건

- 부품 잔액은 음수가 될 수 없음
- 같은 구매·보상 요청의 중복 정산 금지
- 잠긴 코어와 능력을 출격 구성에 넣을 수 없음
- 존재하지 않는 전장·위협도는 기본 전장·위협도 0으로 복구
- 설계 최대 등급을 넘는 연구 구매 거부
- 선행 효과가 없는 조정 능력 구매 거부
- 유료 전장 권한을 잃으면 해당 전장 기록은 보존하되 출격만 막음
- 광고 실패와 구매 실패로 메뉴 입력을 잠그지 않음
- 저장 초기화 중 앱이 종료돼도 구매 권한은 플랫폼에서 복원
- 결과를 두 번 열어도 동일 run ID의 부품은 한 번만 지급
- 시간 변경으로 광고 간격을 우회하지 않도록 누적 gameplay 시간을 사용

## 16. 검증

### 16.1 단위 테스트

- 보스 도달과 최초 처치별 부품 계산
- 3분 미만 참여 보상 제외
- 같은 run ID 중복 정산 방지
- 코어 구매 순서별 `40 / 100 / 160`
- 능력 해금과 최대 등급 비용
- 영구 능력치 단계와 상한
- 응급 정비 키트 1회 발동
- 순차 위협도 해금
- 광고 면제 2런, 3분과 10분 경계
- 확장팩 구매의 광고 제거 권한
- 스킨 구매가 광고를 제거하지 않음
- 저장 schema 마이그레이션과 잘못된 구성 복구

### 16.2 브라우저 자동 테스트

- 앱 시작 시 출격 탭 표시
- 4개 탭과 설정 이동
- 잠긴 코어·능력의 비용과 조건 표시
- 첫 런 결과 뒤 새 코어 하나 구매 가능
- 연구 구매 뒤 다음 런 선택지 풀과 최대 등급 변경
- 실패 런의 도달 보스 보상 유지
- 결과 계속 뒤 광고 조건 판정과 출격 복귀
- 광고 실패가 출격 복귀를 막지 않음
- 새로고침 뒤 부품, 해금, 기록과 구성 유지
- 저장 초기화 뒤 구매 권한 유지

### 16.3 직접 플레이

- 첫 런 뒤 새 코어 선택이 다음 런 동기가 됨
- 12~20런 안에 핵심 해금 대부분을 얻음
- 부품을 영구 능력치와 새 빌드 선택지 중 고민하게 됨
- 사용 숙련도 없이 원하는 연구를 직접 진행할 수 있음
- 광고가 결과 확인과 보상 감정을 끊지 않음
- 짧은 연속 실패에서 광고가 반복되지 않음
- 한 전장 반복 중 새 구슬, 능력과 위협도가 플레이 변화를 제공함

## 17. 구현 순서

1. versioned 저장 데이터와 `MetaProgress`
2. 출격·작업장·기록·상점 4탭 shell
3. 출격 구성과 잠금 검증
4. `RunResult`, 부품 정산과 결과 화면
5. 코어·능력·최대 등급 연구
6. 영구 능력치와 외형 선택
7. 위협도 0 클리어와 기록
8. 광고 조건의 순수 규칙과 개발용 상태
9. 브라우저 전체 사이클 검증
10. 모바일 패키징 시 실제 광고, 결제와 구매 복원 연결

첫 구현 완료 기준은 `출격 → 런 → 결과 → 부품 → 연구 → 새 구성으로 재출격`이 새로고침을 거쳐도 유지되는 것이다.
