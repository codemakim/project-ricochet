# Project Ricochet 정식 모션·VFX 설계

## 1. 목적

전투의 정지된 인상을 제거하고, 플레이어·적·보스·영구 구슬이 역할과 상태를
동작만으로도 전달하게 한다. 공격, 피격, 발동, 파괴가 서로 구분되어야 하며
밀집 전투에서도 적 탄환과 실제 통로를 가리지 않아야 한다.

이 문서는 `2026-08-21-production-art.md`의 Task 7을 대체한다. 현재 구현된 공통
미세 회전과 구슬 아우라는 기반 효과일 뿐 완료 조건으로 보지 않는다.

## 2. 승인된 범위

- 플레이어, 일반 적 4종과 분열체, 보스 3종의 정식 상태 모션
- 기본 구슬 6종과 융합 구슬 9종의 고유 상시 애니메이션
- 발사, 회수, 반사, 직접 타격, 피격, 파괴와 모든 구슬 발동 VFX
- 캐릭터 스킨과 신규 구슬을 추가하기 쉬운 자산·시각 프로필 경계
- 중앙 튜닝, 모바일 효과 상한, 충돌 독립성, 실제 브라우저 검증

다음은 이번 범위에 포함하지 않는다.

- 스킨 상점, 장착 화면, 과금, 저장 스키마
- 새 구슬의 전투 규칙이나 밸런스
- 전투 사운드와 음악
- 출격 전 구슬 선택 및 보상 선택 UI 개편
- 새 적 또는 새 보스

## 3. 핵심 원칙

### 3.1 게임플레이와 외형 분리

충돌체, 체력, 피해, 이동 속도와 발동 판정은 기존 게임플레이 객체가 소유한다.
스킨, 애니메이션 프레임, 발광층과 VFX는 그 상태를 읽어 표현할 뿐이다.

모션 중에도 물리 몸체의 위치와 크기는 바뀌지 않는다. 시각적 반동이나 흔들림은
프레임 교체 또는 물리 몸체가 없는 표현 객체로 처리한다.

### 3.2 스킨은 같은 역할의 외형 교체다

플레이어 스킨은 모든 플레이어와 같은 표시 상자, 중심점과 충돌체를 사용한다.
적 스킨도 같은 적 종류의 표시 상자와 충돌체를 사용한다. 이를 벗어나는 외형은
스킨이 아니라 새 게임플레이 종류로 취급한다.

스킨 선택 UI와 저장은 나중에 추가한다. 이번 작업은 기본 스킨도 동일한 등록
경로를 사용하게 만들어 후속 스킨이 전투 코드를 수정하지 않도록 하는 데 그친다.

### 3.3 새 구슬은 등록으로 확장한다

`OrbTypeId`마다 전투 정의와 별개인 시각 프로필 하나를 가진다. 시각 프로필은
기본 텍스처, 상시 애니메이션층, 팔레트, 궤적과 충돌·발동 효과 키를 선언한다.
새 구슬은 전투 정의와 시각 프로필을 추가하며, `OrbManager`나 `CombatScene`의
구슬 종류별 분기문을 늘리지 않는다.

## 4. 채택 방식

픽셀 캐릭터는 스프라이트 프레임, 고해상도 구슬과 VFX는 부드러운 애니메이션층을
사용하는 하이브리드 방식을 채택한다.

- 런타임 도형만 사용하는 방식은 빠르지만 종류별 개성이 부족해 제외한다.
- 모든 표현을 긴 렌더 영상이나 대형 프레임 시트로 만드는 방식은 용량과 제작
  비용이 커 제외한다.
- 역할이 명확한 짧은 픽셀 프레임과 재사용 가능한 부드러운 에너지층을 조합한다.

별도 범용 애니메이션 엔진은 만들지 않는다. Phaser의 기존 애니메이션, 트윈,
이미지와 Graphics를 사용하고 데이터 등록부만 추가한다.

## 5. 캐릭터 스킨·모션 구조

### 5.1 스킨 프로필

플레이어와 적은 `actor role + skin id`로 시각 프로필을 찾는다. 기본 스킨 ID는
`default`다. 프로필은 다음 정보만 가진다.

- 상태별 텍스처 또는 프레임 키
- 표시 크기와 고정 앵커
- 상태별 프레임 속도와 반복 여부
- 역할 색상과 선택적 발광 색상
- 누락 가능한 선택 상태의 기본 상태 대체 규칙

표시 크기와 앵커는 역할 규격과 일치해야 하며 자산 검증에서 강제한다. 스킨마다
게임플레이 수치를 둘 수 없다.

### 5.2 상태 어휘

공통 상태 이름을 사용하되 역할에 없는 상태는 만들지 않는다.

| 역할 | 필수 상태 |
| --- | --- |
| 플레이어 | idle, move, launch, recover, hurt, defeated |
| 기본 적 | idle, hurt, destroyed |
| 사격 적 | idle, charge, fire, hurt, destroyed |
| 장갑 적 | idle, brace, hurt, destroyed |
| 분열 적 | idle, fracture, split, destroyed |
| 보스 부품 | idle, attack, hurt, broken |
| 보스 코어 | idle, exposed, enraged, defeated |

플레이어와 적의 idle은 2~4프레임, 짧은 반응은 2~5프레임을 기본 범위로 한다.
프레임 수를 맞추기 위해 의미 없는 중간 프레임을 추가하지 않는다.

## 6. 구슬 시각 프로필과 고유 애니메이션

구슬 본체는 현재 `256px` 원본에서 만든 `64px` 선형 샘플링 에셋을 유지한다.
상시 애니메이션은 본체, 내부 에너지층, 외곽층과 소량의 입자로 구성한다. 모든
표현층은 비물리 객체이며 `32px` 충돌 지름과 무관하다.

### 6.1 기본 구슬

| 구슬 | 상시 애니메이션 | 주요 발동 표현 |
| --- | --- | --- |
| 반향 | 중심 렌즈와 외곽 링 교대 맥동 | 반사 누적 링과 잔향 파동 |
| 부식 | 내부 기포 상승과 가스 완류 | 부식 구름 분출과 부착 흐름 |
| 전도 | 표면 전기 아크의 시계 방향 순환 | 목표 사이를 잇는 분기 전격 |
| 관성 | 내부 회전체와 외피의 반대 회전 | 고속 충돌 압축파와 잔상 |
| 분열 | 두 에너지 핵의 공전과 간헐적 분기 | 자식 구슬 분화와 연결선 절단 |
| 폭발 | 열핵의 호흡형 팽창과 미세 불꽃 | 충돌 섬광, 충격파와 화염 잔광 |

### 6.2 융합 구슬

| 구슬 | 상시 애니메이션 | 주요 발동 표현 |
| --- | --- | --- |
| 광자 궤도 | 광륜 공전과 중심 광축 회전 | 관통 광선과 교차 폭발 |
| 공명 군체 | 세 핵의 위상차 공전 | 공명체 분화와 마지막 공명파 |
| 나노 증식체 | 내부 가지의 성장·수축 | 씨앗 산개와 세대 증식 |
| 질량 붕괴탄 | 중력 링 수축과 암부 회전 | 표적 압축 후 붕괴파 |
| 반응로 구슬 | 채널을 따라 흐르는 충전광 | 충전 단계와 완전 방출 |
| 성단 폭격체 | 외곽 포드 순차 점등 | 여섯 방향 탄 분리와 착탄 |
| 거울 회로 | 거울면 전환과 회로 주행광 | 반사 노드와 연결 광선 |
| 융해 코어 | 용융대 순환과 열기 맥동 | 과열 지대와 임계 폭발 |
| 벡터 블레이드 | 칼날축 회전과 방향 표식 이동 | 저장 궤적 절단파 재생 |

상시 애니메이션은 종류 식별에 도움을 주되 적 탄환보다 밝거나 넓게 번지지 않는다.

## 7. 정식 전투 VFX

### 7.1 공통 이벤트

- 플레이어 구슬 발사와 근접·바닥 회수
- 벽 반사와 첫 직접 타격
- 일반 적 피격, 장갑 버팀, 사격 충전·발사, 분열과 파괴
- 플레이어 피격과 패배
- 보스 부품 파괴, 페이즈 전환, 코어 노출·격노·격파

### 7.2 구슬 이벤트

기본·융합 구슬의 기존 의미 이벤트를 그대로 사용한다. 전투 로직은
`visual event id + position + direction + intensity`만 전달하고 시각 프로필이
텍스처, 색상, 크기, 수명과 발생량을 결정한다.

같은 전투 이벤트에서 효과를 중복 생성하지 않는다. 현재 `CombatScene`의 명명된
피드백 경로를 시각 이벤트 경계로 정리하며 두 번째 VFX 프레임워크를 만들지 않는다.

## 8. 자산 배치와 등록

권장 소스 경로:

```text
assets-source/combat/actors/<role>/<skin-id>/
assets-source/combat/orbs-hd/<orb-id>/
assets-source/combat/vfx/<event-id>/
```

권장 런타임 경로:

```text
public/assets/combat/actors/<role>/<skin-id>/
public/assets/combat/orbs/<orb-id>/
public/assets/combat/vfx/<event-id>/
```

이미지 매니페스트는 정적 배열을 손으로 복제하지 않고 스킨·구슬·VFX 프로필에서
필요한 자산 목록을 합성한다. 픽셀 캐릭터는 nearest, 구슬과 VFX는 linear를 쓴다.

## 9. 중앙 튜닝과 성능

다음 값은 `GAME_TUNING.visual` 한 곳에서 관리한다.

- 상태별 프레임 속도와 짧은 반응 시간
- 구슬 내부층·외곽층의 회전, 맥동, 투명도
- 궤적 간격, 입자 수, 효과 크기와 수명
- 종류별 고유 효과의 최대 동시 개수
- 모바일 전체 VFX 상한

일회성 효과는 기존 Phaser 객체를 짧게 생성해 파괴하거나 작은 풀을 사용한다.
풀은 반복 생성이 실제로 많은 효과에만 둔다. 정지·일시정지·장면 종료 시 남은
타이머와 표현 객체를 모두 정리한다.

## 10. 검증 기준

### 10.1 자동 검증

- 모든 기본 스킨이 역할별 필수 상태를 제공한다.
- 스킨 프레임의 크기, 앵커와 샘플링이 역할 규격과 일치한다.
- 모든 `OrbTypeId`가 시각 프로필과 필수 자산을 가진다.
- 구슬 15종의 상시 애니메이션 프로필이 서로 다른 정체성 키를 가진다.
- 모션 전후 플레이어, 적, 구슬과 보스 충돌체의 위치·크기가 같다.
- VFX 객체는 물리 몸체를 갖지 않으며 제한 시간 뒤 제거된다.
- 장면 종료 뒤 애니메이션 타이머와 표현 객체가 남지 않는다.

### 10.2 실제 화면 검증

데스크톱과 모바일에서 다음 장면을 캡처하고 실제 크기로 검사한다.

- 플레이어 이동·발사·회수·피격
- 일반 적 밀집 전투, 사격 경고와 분열
- 기본 구슬 6종과 융합 구슬 9종의 상시·발동 상태
- 보스 3종의 부품 파괴와 코어 격노
- 여러 구슬과 적 탄환이 동시에 존재하는 고밀도 전투

종류를 움직임만으로 대략 구분할 수 없거나, 효과가 적 탄환·조준선·통로를 가리거나,
30초 전투 후 효과 수가 계속 증가하면 통과하지 않는다.

## 11. 구현 순서

1. 역할별 스킨 프로필과 구슬 시각 프로필 계약
2. 자산 매니페스트 합성과 검증
3. 플레이어·일반 적·보스 상태 모션 제작
4. 기본 구슬 6종 고유 상시 애니메이션
5. 융합 구슬 9종 고유 상시 애니메이션
6. 공통 전투 VFX와 기본 구슬 발동 VFX
7. 융합 구슬·보스 전용 VFX
8. 밀집 모바일 화면, 성능과 정리 검증

각 단계는 대표 화면을 확인하지만 전체 브라우저 회귀 검사는 마지막 한 번만 실행한다.

## 12. 완료 조건

- 모든 캐릭터가 역할에 맞는 대기·행동·피격·파괴 모션을 가진다.
- 구슬 15종이 각각 고유한 상시 애니메이션과 발동 표현을 가진다.
- 기본 스킨도 등록형 경로를 사용하고 새 스킨이 전투 로직 변경 없이 추가된다.
- 새 구슬은 전투 정의와 시각 프로필 등록으로 표현 계층에 연결된다.
- 모든 표현이 기존 충돌과 밸런스를 바꾸지 않는다.
- 모바일 고밀도 전투에서 가독성과 성능 기준을 통과한다.
