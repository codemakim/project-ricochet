# Project Ricochet 격자 진형 전투 개편 설계

## 1. 목적

현재의 작고 많은 독립 적을 다음 전장으로 개편한다.

- 큼직한 타일형 적과 명확한 빈 공간
- 일반전은 8열 혼합 진형
- 보스전은 큰 보스가 전장을 점유하는 대형 구도
- 적 배치는 격자로 관리하되 움직임과 충돌은 부드러운 실제 좌표 사용
- 고정 배치와 규칙 기반 변형을 같은 데이터 구조로 구성
- 구슬 하나로 시작하고 초기에 두 번째 구슬을 확정해 성장 체감 확보
- 플레이어의 비선형 화력 증가에 맞춘 구간형 적 성장

이 문서는 `2026-07-29-three-boss-meta-loop-design.md`의 시작 구슬 3개 규칙과 기존 점 단위 적 배치를 대체한다. 영구 코어 해금과 출격 흐름은 유지한다.

## 2. 전장 규격

전장은 논리적으로 8열이다. 행 수는 화면 크기에 고정하지 않고 위쪽에서 공급되는 진형 덩어리의 배치 단위로 사용한다.

적 크기 규격은 다음으로 시작한다.

| 분류 | 점유 크기 | 용도 |
|---|---|---|
| 일반 | `1×1` | 기본 적, 사격 적 |
| 중형 | `2×1`, `1×2` | 분열 적, 방벽형, 포대형 |
| 대형 | `2×2` | 고체력 적, 범위 공격 적 |
| 엘리트 | `3×2` | 일반 구간의 핵심 표적 |
| 보스 | `4×2`~`6×4` | 보스 본체와 부속물 |

`6×6`은 초기 범위에서 제외한다. 모바일 세로 화면의 조준 통로를 과도하게 막을 가능성이 크기 때문이다.

격자는 다음 용도로만 사용한다.

- 생성 위치 결정
- 여러 칸 점유 검사
- 진형 데이터 검증
- 분열 위치 결정
- 보스 이동 가능 영역 계산

렌더링, 구슬 충돌, 적 탄환 충돌과 이동은 실제 월드 좌표를 사용한다. 화면에 한 칸씩 끊겨 내려오는 움직임은 없다.

## 3. 적과 점유 모델

각 적은 모든 점유 칸에 중복 저장하지 않고 기준 칸과 크기만 가진다.

```ts
type FormationEnemySpec = {
  kind: EnemyKind;
  column: number;
  row: number;
  width: number;
  height: number;
  hpMultiplier?: number;
};
```

생성 시 임시 2차원 점유표에 `[column, column + width)`와 `[row, row + height)` 범위를 표시한다. 범위가 전장 밖이거나 이미 점유된 칸과 겹치면 해당 배치는 유효하지 않다.

점유표는 배치 검증과 생성에만 사용한다. 런타임 적 상태의 권위 데이터는 각 적 엔티티다. 별도 범용 격자 프레임워크나 타일맵 의존성은 만들지 않는다.

분열 적은 `2×1`로 생성한다. 사망 시 원래 점유했던 두 칸을 기준으로 `1×1` 파편 둘을 생성한다. 다른 적과 약간 시각적으로 겹치는 것은 허용하지만 전장 벽 밖으로 나가거나 벽을 넘어 생성되지는 않는다.

## 4. 진형 이동

일반 적은 개별 하강 속도를 가지지 않고 진형 원점에 상대적인 위치를 유지한다.

```text
worldX = formationOriginX + column × cellWidth
worldY = formationOriginY + row × cellHeight
formationOriginY += descentSpeed × deltaTime
```

따라서 모든 일반 적은 현재 게임처럼 픽셀 단위 등속으로 부드럽게 내려온다. 논리 행 단위 이동, 정지 후 이동, 칸 스냅은 사용하지 않는다.

죽은 적의 자리는 빈 공간으로 남는다. 이 공간은 구슬의 도탄 통로이자 보스의 좌우 이동 가능 영역이 된다.

특수 적은 공격 행동을 위해 진형 기준 위치에서 제한적으로 벗어날 수 있다. 행동 종료 후 원래 슬롯으로 복귀한다. 첫 구현에서는 기존 사격 적처럼 자리를 유지하는 적만 이전하며, 진형 이탈 행동은 신규 적을 만들 때 추가한다.

## 5. 진형 공급과 스테이지 구성

일반 전투는 전장을 한 번에 채우지 않는다. `2~5행` 높이의 진형 덩어리를 화면 위쪽에서 연속 공급한다.

각 덩어리는 다음 두 요소로 구성한다.

1. 배치 골격: 밀집부, 빈 통로와 큰 적이 들어갈 자리
2. 변형 규칙: 적 종류 교체, 일부 칸 비우기, 좌우 반전과 허용 범위 안의 위치 변화

세 가지 생성 방식을 같은 진형 명세로 지원한다.

- 고정형: 튜토리얼, 보스 전조, 의도된 전투
- 규칙형: 일반 반복 구간
- 혼합형: 고정 골격에 적 종류와 일부 빈칸을 seeded 변형

기본은 혼합형이다. 완전 랜덤 배치가 만드는 부자연스러운 체크무늬와 막힌 화면을 피하면서 반복감을 줄인다.

```ts
type FormationChunkDefinition = {
  id: string;
  rows: number;
  enemies: FormationEnemySpec[];
  mutations?: FormationMutation[];
  minStage: number;
  weight: number;
};
```

스테이지 데이터는 사용할 덩어리 풀, 공급 간격, 적 종류 풀, HP 배율, 대형 적 비율과 보스 ID를 지정한다. 새로운 일반 스테이지는 엔진 코드를 추가하지 않고 데이터 조합으로 만든다.

보스 진입 시간이 가까워지면 새 덩어리 공급을 중단한다. 남은 일반 적을 강제로 제거하지 않고 보스와 함께 유지한다.

## 6. 보스 구도

보스도 같은 8열 점유 규칙을 사용하지만 별도 보스 진형에 속한다. 큰 본체와 부속물이 `4×2`~`6×4` 영역을 차지해 일반전보다 적고 큰 표적이 남는 구도를 만든다.

보스는 점유 가능한 빈 가로 범위 안에서 부드럽게 이동한다. 일반 적이나 부속물이 이동 영역을 막고 있으면 그 방향으로 더 진행하지 않는다. 주변 적과 부속물이 파괴되면 이동 범위가 자연스럽게 넓어진다.

기존 보스의 파츠별 collider 누락은 이전 과정에서 함께 바로잡는다. 모든 공격 가능한 시각 파츠는 실제 충돌 영역과 체력을 가져야 한다.

## 7. 시작 구슬과 초기 성장

런은 출격 구성에서 선택한 영구 코어 구슬 하나로 시작한다. 기본 자동 보조무기는 지급하지 않는다.

첫 레벨업은 전투 시작 후 약 `20~30초` 안에 도달하도록 조정한다. 첫 레벨업 선택은 다음 규칙을 가진다.

- 두 번째 영구 구슬 추가를 확정 제공
- 해금된 영구 코어 중 종류 선택
- 해금 코어가 하나뿐이면 같은 종류가 자동 후보
- 구슬 수 증가와 구슬 종류 선택이 한 보상에서 함께 일어남

이후 구슬 추가는 일반 보상 풀에 들어간다. 현재 구슬 수가 해당 스테이지의 예상 수보다 적으면 선택지 가중치를 올리고, 충분하면 기본 가중치로 복귀한다. 최대 구슬 수는 중앙 설정값 하나를 사용한다.

보조무기는 자동 기본 공격이 아니라 런 중 획득하는 빌드 선택지다. 자동 사격, 수평·수직 절단선과 가스 살포 같은 기존 발동 무기가 이 역할을 맡는다.

메타 진행에서 새 영구 코어를 해금하면 첫 레벨업의 두 번째 구슬 선택 폭도 넓어진다.

## 8. 적 체력과 파워 커브

플레이어 화력은 구슬 수와 효과 조합 때문에 비선형으로 증가한다. 적 체력을 단일 선형 공식이나 무제한 지수 공식으로 올리지 않고 구간별 기대 화력에 맞춘다.

| 구간 | 기대 상태 | 적 구성과 체력 방향 |
|---|---|---|
| 준비 | 구슬 1개 | `1×1` 중심, 일반 적 직접 타격 약 1~3회 |
| 형성 | 구슬 2~3개 | 중형·사격 적 추가, 완만한 HP 상승 |
| 증폭 | 확률 효과와 분열 연계 | 대형·엘리트 비율 및 HP 상승폭 증가 |
| 완성 | 복수 시너지 활성 | 고체력 대형 적과 복합 탄환 패턴 |
| 보스 | 해당 시점 예상 빌드 | 보스별 파츠와 페이즈로 별도 조정 |

스테이지는 다음과 같은 기대 구간만 참조한다.

```ts
type StagePowerBand = {
  expectedOrbCount: number;
  normalHpMultiplier: number;
  eliteHpMultiplier: number;
  largeEnemyRatio: number;
};
```

실제 플레이어 빌드의 DPS를 읽어 적 체력을 실시간 보정하지 않는다. 좋은 빌드를 만들었을 때 적을 압도하는 보상을 유지하기 위해서다.

난이도 상승 수단의 우선순위는 다음과 같다.

1. 적 크기와 점유 구성
2. HP와 엘리트 비율
3. 공격 패턴과 탄환 조합
4. 진형 공급 밀도
5. 하강 속도

하강 속도 증가는 가장 보수적으로 사용하며 기본적으로 스테이지 사이에서 유지한다.

## 9. 기존 데이터 이전

개편은 전면 교체가 아니라 현재 8열 진형 시스템의 확장으로 진행한다.

1. 기존 점 단위 적을 기본 `1×1`로 읽을 수 있게 한다.
2. 점유 검증과 다중 칸 크기를 추가한다.
3. 일반전 한 스테이지만 새 혼합 덩어리로 이전한다.
4. 플레이 검증 후 나머지 일반 스테이지를 이전한다.
5. 분열 적과 대형 적을 새 점유 규격으로 전환한다.
6. 세 보스의 본체와 파츠를 새 규격으로 이전한다.
7. 시작 구성과 첫 레벨업을 구슬 1개 규칙으로 변경한다.
8. 새 전장의 측정값으로 HP와 공급 밀도를 조정한다.

이전 중 구형과 신형 스테이지를 동시에 장기간 유지하지 않는다. 첫 스테이지 검증이 끝나면 나머지를 바로 변환하고 호환 경로를 제거한다.

## 10. 완료 기준

- 일반 전장이 논리 8열에서 `1×1`~`3×2` 적을 겹침 없이 배치한다.
- 진형이 행 단위 끊김 없이 현재와 같은 등속으로 하강한다.
- `2~5행` 덩어리가 고정·규칙·혼합 방식으로 연속 공급된다.
- 같은 seed는 같은 배치 변형을 만든다.
- 분열 적 `2×1`이 유효한 `1×1` 두 마리로 분리된다.
- 죽은 적의 공간이 빈 도탄 통로로 남는다.
- 보스와 파츠가 큰 점유 영역과 실제 collider를 가진다.
- 런은 영구 구슬 하나로 시작한다.
- 첫 레벨업에서 해금 코어 중 두 번째 구슬을 확정 선택한다.
- 구슬 부족 시 추가 구슬 선택 가중치가 보정된다.
- 스테이지 HP는 기대 파워 구간을 따르며 실시간 빌드 추적을 하지 않는다.
- 데스크톱과 모바일에서 조준, 이동, 충돌과 UI가 정상 동작한다.

## 11. 검증

### 단위 테스트

- 여러 칸 점유의 경계 및 겹침 거부
- 유효한 혼합 크기 진형 생성
- seeded 변형의 재현성
- 진형 원점과 적 월드 좌표 계산
- 덩어리 공급 순서와 보스 전 공급 중단
- 분열 위치가 전장 안에 유지됨
- 첫 레벨업의 구슬 확정 후보
- 해금 코어 필터와 구슬 부족 가중치
- 스테이지 파워 구간 적용

### 통합 검증

- 첫 스테이지 새 전장에서 밀집부와 빈 통로 확인
- 진형 하강이 시각적으로 끊기지 않음
- 구슬이 크기가 다른 적의 실제 외곽에서 충돌
- 폭발·전도·관통이 큰 적과 밀집 진형에 정상 적용
- 보스 파츠가 보이는 영역과 동일하게 피격됨
- 구슬 1개 시작부터 첫 레벨업까지 전투가 루즈하거나 불합리하지 않음
- 두 번째 구슬 획득 직후 화력 증가가 명확함

브라우저 전체 검증은 일반전 한 스테이지의 수직 슬라이스가 완성됐을 때 한 번, 전체 이전 완료 후 한 번 실행한다.

## 12. 후속 범위

이번 개편에 다음은 포함하지 않는다.

- 신규 보조무기 추가
- 신규 영구 코어 추가
- 완성 그래픽과 사운드
- 전장 팩과 핀볼·당구 변형
- 실시간 난이도 적응
- 진형 편집기

새 데이터 구조로 스테이지를 충분히 작성한 뒤 편집 작업이 실제 병목일 때만 전용 편집기를 검토한다.
