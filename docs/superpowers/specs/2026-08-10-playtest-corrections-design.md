# 스테이지 1~3 플레이 피드백 수정 설계

## 목표

스테이지 2 보스와 스테이지 3 초입까지의 플레이에서 확인된 치명적 오동작과 전투 감각 문제를 세 묶음으로 수정한다.

1. 융합 효과의 구슬별 격리, 2보스 구조물 동작, 인게임 발견 표시를 바로잡는다.
2. 모든 일반 적 편성에 실제 구슬 통로를 보장하고 첫 구슬 구간을 단축한다.
3. 보조 효과가 실제 처치에 기여하도록 수치를 다시 맞추고 작업장을 반응형 격자 UI로 개편한다.

그래픽·사운드 최종 제작, 신규 적·보스·구슬 추가, 저장 스키마 변경은 범위 밖이다.

## 확인된 현재 원인

### 작업장 잘림

`html`, `body`, `#app-root`가 모두 `overflow: hidden`이고 작업장에 별도 스크롤 영역이 없다. 기본 구슬 6종과 융합 9종을 세로 목록으로 이어 붙여 화면 높이를 넘으면 아래 콘텐츠와 돌아가기 버튼에 접근할 수 없다.

### 융합 효과 오인 또는 누출

현재 `OrbStore.fuseOrbs`는 선택한 첫 구슬의 ID와 타입만 융합으로 바꾸고 두 번째 재료만 제거한다. 직접 타격 이벤트도 해당 구슬 레코드의 `coreType`을 전달한다. 코드상 전역 융합 타입은 없으므로, 동일 재료 구슬을 함께 둔 실제 재현으로 다음 두 경우를 구분해야 한다.

- 다른 기본 구슬까지 융합 효과를 내는 실제 타입 누출
- 하나의 융합 구슬이 같은 물리 프레임에 여러 적을 맞혀 피드백을 여러 번 만든 발사원 오인

수정은 재현 결과에 따라 공통 이벤트 경계 한 곳에서 한다. 증상별 예외 처리는 추가하지 않는다.

### 약한 보조 피해

스테이지 2 기본 적 HP는 `3 × 1.6 = 4.8`이다. 부식 피해는 레벨이 올라도 틱당 `0.2`로 고정되어 전체 지속시간을 맞혀도 직접 타격 한 번보다 약하다. 여러 일반 효과와 융합도 적 HP 성장에 비해 낮은 소수점 피해에 머물러 처치 원인으로 보이기 어렵다.

### 막힌 편성

현재 고정·혼합 템플릿에도 빈칸이 있지만 혼합 템플릿은 절차 생성 단계가 목표 셀 수까지 다시 채운다. 절차 편성도 통로를 계약으로 보장하지 않는다. 따라서 화면에 빈칸이 있더라도 위아래로 연결된 구슬 통로나 내부 반사 공간은 쉽게 사라진다.

### 2보스의 중앙 고정과 통과

2보스는 `shielded → telegraph → exposed` 주기마다 구조물을 중앙 회수 위치와 전개 위치 사이에서 즉시 이동시킨다. 회수 상태의 세로 반사판은 피해만 받고 물리 반사는 하지 않도록 명시되어 있다. 플레이어에게는 구조물 파괴 뒤 대열이 중앙에 고정되고 구슬이 통과하는 치명적 버그로 보인다.

### 인게임 `???`

레벨업 카드와 융합 재료 선택 화면이 메타 발견 상태를 그대로 사용해 첫 획득 전에 이름과 전체 설명을 가린다. 선택에 필요한 정보까지 숨겨 빌드 결정을 할 수 없다.

## 작업 묶음 1: 정확성 및 정보 표시

### 융합 효과 격리

- 동일 기본 구슬 두 개와 융합 재료 한 개를 구성한다.
- 그중 선택된 ID만 융합하고 남은 기본 구슬의 타입·레벨·고유 효과가 유지되는지 검사한다.
- 융합 구슬과 남은 기본 구슬을 각각 적에게 충돌시켜 생성된 효과의 발사원을 검사한다.
- 전투 피드백 오브젝트에는 개발·테스트용 `sourceOrbId` 데이터를 붙인다. 사용자 화면에는 ID를 출력하지 않는다.
- 실제 누출이면 `OrbManager → DirectHitEvent → CombatScene` 공통 경계에서 고친다.
- 타입은 격리되어 있고 한 구슬의 다중 충돌이 원인이면 동일 구슬·동일 물리 프레임의 중복 피드백만 합친다. 서로 다른 시점의 정상 다중 타격은 유지한다.

### 2보스

- 구조물 회수와 중앙 정렬을 제거한다.
- 사수와 반사판은 첫 전개 위치에서 유지한다.
- 살아 있는 반사판은 `shielded`, `telegraph`, `exposed` 모두에서 이동하고 구슬을 물리 반사한다.
- 코어만 보호막, 경고, 노출 주기를 유지한다.
- 파괴된 구조물은 숨김·충돌 비활성 상태를 유지하며 다른 구조물 파괴나 페이즈 전환으로 재배치되지 않는다.
- 네 구조물이 모두 파괴되면 기존처럼 코어가 영구 노출되고 격노 공격을 사용한다.

### 인게임 발견 정보

- 레벨업의 기본 구슬 추가·융합 카드는 발견 여부와 무관하게 실제 이름과 전체 효과를 표시한다.
- 융합 재료 선택 화면도 실제 결과 이름과 결과 레벨을 표시한다.
- 선택을 완료하면 기존처럼 발견 목록에 기록한다.
- 런 밖 작업장 도감은 획득 전 실루엣, 역할 힌트, `???`를 유지한다.
- 저장 스키마와 발견 조건은 바꾸지 않는다.

## 작업 묶음 2: 반사 통로와 초반 성장

### 편성 통로 계약

모든 편성은 아래에서 들어가 위쪽 또는 내부 주머니까지 이어지는 최소 한 칸 폭의 빈 경로를 가져야 한다. 단순히 서로 떨어진 빈칸 몇 개는 통로로 인정하지 않는다.

- 세로 관통로, 꺾인 통로, 측면 반사 주머니 등 소수의 고정 빈칸 마스크를 둔다.
- 고정·혼합 템플릿은 선택된 마스크 칸에 적을 배치하지 않는다.
- 절차 채우기도 같은 금지 셀을 사용한다.
- 연속 두 편성은 같은 통로 축을 공유한다. 편성 순번을 둘씩 묶어 마스크를 선택하므로 별도 런타임 상태는 추가하지 않는다.
- 다음 묶음은 통로 위치나 형태를 바꿔 한 중앙 레인만 반복되는 문제를 막는다.
- 다칸 적도 통로 금지 셀과 한 칸이라도 겹치면 배치하지 않는다.
- 기존 셀 최소·최대, 적 종류 가중치, 매끄러운 등속 하강은 유지한다.

### 첫 레벨업

- 첫 레벨업 요구 XP만 `8`에서 `5`로 낮춘다.
- 이후 요구량 `12 + level × 5`는 유지한다.
- 기존 초반 보상 구성인 구슬 카드 2장과 능력 카드 1장을 유지한다.
- 이 묶음에서는 적 HP, 밀도, 하강 속도를 바꾸지 않는다.

## 작업 묶음 3: 효과 피해와 작업장

### 피해 목표

- 일반 보조 효과의 1회 발동 또는 전체 지속 피해는 같은 성장 구간 기본 적 HP의 약 30~50%를 목표로 한다.
- 일반 효과는 이미 직접 타격을 받은 적을 자주 마무리해야 한다.
- 고레벨 기본 구슬과 융합은 온전한 기본 적 처치 또는 다수 약화 적 연쇄 처치가 가능해야 한다.
- 직접 타격은 조준과 회수의 핵심으로 남지만 유일한 실질 피해원이 되어서는 안 된다.

### 수치 구조

- 부식의 `damagePerTick` 고정값을 5레벨 곡선으로 바꾼다.
- 폭발, 전도, 분열 임시 구슬, 일반 보조 무기와 융합 9종의 총 피해 예산을 적 HP와 직접 타격 피해에 맞춰 검토한다.
- 조정값은 기존 `GAME_TUNING` 배열과 검증 함수에만 둔다. 장면 코드에 단계별 배율을 추가하지 않는다.
- `effect-output`, 확률, 지속시간, 범위 강화와 결합했을 때 과도하게 곱연산되지 않는지 최대 랭크도 검사한다.
- 보스 보조 피해 제한과 보스별 부위 상한은 유지해 일반 적 화력 상향이 보스 순간 삭제로 이어지지 않게 한다.

### 효과 처치 가시성

- 지속 피해, 전도, 폭발·융합 피해는 기존 효과 색상의 짧은 피해 숫자를 표시한다.
- 보조 효과로 적이 죽으면 같은 색상의 짧은 처치 섬광을 표시한다.
- 수명과 동시 표시 수는 기존 피드백 지속시간과 전역 효과 상한을 사용한다. 새 파티클 시스템은 만들지 않는다.

### 작업장 A1

데스크톱과 모바일은 같은 카드 데이터를 사용하고 상세 표시 방식만 CSS 미디어 쿼리로 바꾼다.

- 기본 구슬과 융합 기록을 탭으로 분리한다.
- 선택 카드는 정방형이며 구슬 이미지, 이름, 가격 또는 해금 상태만 표시한다.
- 데스크톱은 좌측 3열 격자와 우측 고정 상세 패널을 사용한다.
- 모바일은 3열 격자 위에 고정 하단 시트를 띄운다. 카드 선택 직후 현재 뷰포트에 나타나며 자동 스크롤하지 않는다.
- 하단 시트는 바깥 영역 탭, 닫기 버튼, `Escape`로 닫는다.
- 시트가 열리면 포커스를 시트로 옮기고 닫으면 선택 카드로 복귀한다.
- 작업장 화면은 세로 스크롤을 허용하고 헤더·탭은 상단에 유지한다.
- 현재 절차형 구슬의 색과 심볼을 이용한 가벼운 DOM 아이콘을 사용한다. 최종 래스터 아트 파이프라인은 추가하지 않는다.
- 미발견 작업장 항목은 실루엣, 역할 힌트와 `???`를 유지한다.

## 데이터 흐름

1. 보상 선택은 실제 정의를 읽어 이름과 효과를 보여준다.
2. 구슬 추가·강화·융합 완료 후에만 기존 발견 목록을 갱신한다.
3. 영구 구슬 충돌은 구슬 ID와 타입을 직접 타격 이벤트로 전달한다.
4. 전투 장면은 해당 이벤트의 타입에 해당하는 효과만 만들고 피드백에 발사원 ID를 기록한다.
5. 편성 생성은 순번으로 통로 마스크를 고르고, 템플릿과 절차 채우기가 같은 금지 셀을 공유한다.
6. 피해 수치는 중앙 튜닝에서 프로필로 변환된 뒤 기존 직접·범위·선분 피해 API를 사용한다.
7. 작업장 카드 선택은 데스크톱 상세 패널 또는 모바일 하단 시트에 같은 정의를 전달한다.

## 오류 및 경계 처리

- 통로 마스크 때문에 프로필의 최소 셀 수를 채울 수 없으면 해당 편성 정의를 검증 단계에서 거부한다.
- 융합 재료가 선택 화면 진입 뒤 달라지면 기존처럼 취소하고 보상 화면으로 복귀한다.
- 파괴된 보스 부위는 위치 갱신, 충돌, 공격 예약 대상에서 제외한다.
- 모바일 상세 시트가 열린 상태에서 화면 크기가 바뀌어도 선택된 코어와 포커스를 유지한다.
- 작업장 구매 실패 메시지는 현재 상태 영역을 재사용한다.

## 검증

### 단위 테스트

- 동일 타입 구슬 중 선택된 ID만 융합되고 다른 구슬의 타입·레벨·효과 상태가 유지된다.
- 융합·기본 구슬 직접 타격 계획이 구슬별로 섞이지 않는다.
- 2보스의 모든 살아 있는 반사판이 모든 비격파 페이즈에서 이동·반사한다.
- 개별 부위 파괴와 페이즈 전환이 남은 부위를 중앙으로 옮기지 않는다.
- 보상 카드가 미발견 이름과 전체 설명을 표시하지만 발견 기록은 선택 뒤에만 바뀐다.
- 다수 시드와 모든 프로필에서 연결 통로가 존재하고 다칸 적이 금지 셀을 침범하지 않는다.
- 첫 XP는 5이며 두 번째 이후 곡선은 기존 값을 유지한다.
- 일반·융합 효과의 최소·최대 레벨 피해 예산이 목표 범위와 보스 상한을 지킨다.
- 작업장 카드, 탭, 상세 정보와 구매 상태가 진행 데이터에서 올바르게 렌더링된다.

### 브라우저 검증

- 두 전도 구슬 중 하나만 융합해 각각 충돌시키고 효과 발사원과 화면 피드백을 확인한다.
- 2보스의 전체 주기와 부위 파괴 중 구조물 위치, 반사, 이동을 확인한다.
- 스테이지 1~3 편성 표본에서 구슬이 통로에 진입해 위쪽과 내부에서 연속 반사하는지 확인한다.
- 일반 효과와 융합 효과가 직접 타격 없이 약화 적을 처치하는 장면을 확인한다.
- 좁은 모바일 뷰포트에서 작업장 카드 탭 즉시 하단 시트가 보이고 추가 스크롤이 필요 없는지 확인한다.
- 데스크톱에서 격자와 우측 상세 패널이 동시에 보이고 전체 작업장 항목과 돌아가기 버튼에 접근 가능한지 확인한다.

## 작업 순서와 체크포인트

1. 정확성 및 정보 표시를 구현·검증·커밋한다.
2. 반사 통로와 첫 레벨업을 구현·검증·커밋한다.
