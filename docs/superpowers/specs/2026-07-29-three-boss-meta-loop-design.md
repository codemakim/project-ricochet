# Project Ricochet 3보스 완성 루프 설계

## 1. 목적과 범위

현재 33종 일반 능력과 두 보스까지 구현된 전투를 다음 순서로 제품 한 사이클까지 완성한다.

1. 보스 희귀 보상 개편
2. 제3 보스와 3단계 전장 추가
3. `출격 → 런 → 결과 → 부품 → 코어 해금 → 재출격` 외부 루프 추가

이 문서는 다음 기존 설계를 구체화한다.

- `2026-07-27-run-build-system-redesign.md`
- `2026-07-27-meta-progression-monetization-design.md`

두 문서와 충돌할 때 이 문서의 3보스 흐름과 최종 보스 처리 규칙을 우선한다.

이번 범위에는 기록 탭, 상점, 광고 SDK, 결제, 영구 능력치, 능력 연구, 외형과 신규 일반 적을 넣지 않는다.

## 2. 완료 기준

- 보스 1과 2는 현재 빌드에 맞는 희귀 보상 3개를 제시한다.
- 세 번째 일반 구간과 제3 보스를 연속해서 플레이할 수 있다.
- 마지막 보스 처치 시 전투용 보상을 고르지 않고 결과 화면으로 이동한다.
- 결과에서 부품을 한 번만 정산한다.
- 첫 유효 런 뒤 새 영구 코어 하나를 구매할 수 있다.
- 시작 영구 구슬 3개를 해금된 코어 안에서 구성할 수 있다.
- 새로고침 뒤 부품, 해금과 출격 구성이 유지된다.

## 3. 구현 순서

### 3.1 보스 희귀 보상

기존 1·2차 전용 보상 11종을 다음 9종의 공용 데이터 목록으로 교체한다.

| ID | 표시명 | 등장 조건 | 효과 |
|---|---|---|---|
| `auxiliary-link` | 보조체 연결 | 분열 보유 | 임시 구슬이 보유 확률형 효과를 기본 확률의 25%로 발동 |
| `cross-cut` | 교차 절단 | 수평 또는 수직 절단선 보유 | 한 방향 절단선 발동 시 반대 방향도 60% 피해로 발동 |
| `gas-ignition` | 가스 점화 | 폭발과 부식 코어 보유 | 폭발이 가스와 겹치면 남은 지속 피해 50%를 즉시 적용하고 제거 |
| `recursive-split` | 재귀 분열 | 분열 보유 | 임시 구슬이 계보당 한 번 20% 확률로 임시 구슬 하나 생성 |
| `inertia-retention` | 관성 보존 | 관성 코어 보유 | 관성 속도 보너스가 두 번째 직접 타격 뒤 종료 |
| `complete-cycle` | 완전 순환 | 재장전 과충전 보유 | 과충전 첫 타격 처치 시 해당 영구 구슬 즉시 무충돌 귀환 |
| `direct-link` | 직격 연동 | 재장전 과충전과 발동 효과 보유 | 과충전 배율의 30%를 같은 타격의 보조 피해에 적용 |
| `superconducting-circuit` | 초전도 회로 | 전도 코어 보유 | 전도 요구 타격 -1, 대상당 피해 +20% |
| `resonance-rupture` | 공명 파열 | 반향 코어 보유 | 최대 공명 직접 타격에 작은 확정 충격파 발생 |

보상 정의는 ID, 조건과 표시 정보를 한곳에 둔다. 수치는 `GAME_TUNING.relics`에서 참조한다. 별도 범용 효과 언어나 이벤트 버스는 만들지 않는다.

보스 1과 2는 아직 보유하지 않은 적격 보상을 seeded shuffle한 뒤 3개를 제시한다. 적격 보상이 3개 미만이면 조건 없는 보조 선택지를 추가하지 않고, 보유한 일반 능력 중 하나를 즉시 1등급 올리는 기존 레벨업 카드로 빈자리를 채운다. 최대 등급 능력은 제외한다.

보조체 연결과 재귀 분열은 기존 임시 구슬 30개 상한과 계보 제한을 지킨다. 보조 피해는 다시 효과를 발동하지 않는다.

### 3.2 제3 보스 `siege-platform`

`StageDefinition`에 `default-3`을 추가한다. 제3 구간은 기존 적 카탈로그와 대형 프로필을 사용하고 HP, 수, 특수 적 비율로 난도를 높인다. 하강 속도 배율은 1을 유지한다.

보스는 화면 상단을 차지하는 큰 공성 플랫폼이다.

- 중앙 코어 1개
- 좌우 포대 2개
- 중앙 방어 모듈 1개
- 파츠는 원하는 순서로 파괴 가능
- 코어는 파츠가 하나라도 살아 있으면 잠김
- 플랫폼은 상단 경계 안에서 기존 보스보다 느리게 좌우 이동

공격은 공용 패턴과 파라미터 조합으로 구성한다.

- 조준탄: 짧은 간격으로 한 발
- 확산탄: 설정된 발수와 각도
- 수직 낙하물: 보스 위치와 무관한 x좌표에서 생성
- 이동 레이저: 예고선을 표시한 뒤 세로 피해선이 좌우로 이동

좌우 포대는 각각 조준탄과 확산탄을 담당한다. 방어 모듈은 낙하물과 이동 레이저를 담당한다. 파츠가 파괴되면 해당 공격이 중단된다.

모든 파츠가 파괴되면 코어가 영구 노출된다. 이때 이동 범위가 넓어지고 조준탄, 확산탄과 이동 레이저를 더 짧은 간격으로 조합한다. 코어는 정지 표적이 되지 않는다. 탄환 수, 발사 간격, 탄속, 레이저 예고 시간·폭·속도와 보스 이동 속도는 중앙 설정에서 바꿀 수 있다.

이동 레이저는 독립된 공용 순수 패턴 명세와 Phaser 적용 코드로 나눈다. 예고 중에는 피해가 없고, 활성 구간에서 플레이어당 한 번의 무적 시간 규칙을 사용한다. 일시정지, 패배, 보스 처치와 장면 종료 시 예고선과 활성 레이저를 모두 제거한다.

제3 보스 처치 시 런이 끝나므로 전투용 희귀 보상을 제시하지 않는다. `EncounterDirector`는 다음 스테이지 존재 여부로 `bossRewardPaused`와 `runComplete`를 결정한다.

### 3.3 외부 반복 루프

첫 수직 단계는 두 화면만 만든다.

- `출격`: 시작 코어 3개와 출격 버튼
- `작업장/코어`: 코어 해금과 부품 잔액

앱은 출격 화면에서 시작한다. 전투 시작 시 메뉴를 숨기고 기존 `CombatScene`을 시작한다. 패배 또는 제3 보스 처치 시 `RunResult`를 받아 결과 overlay를 표시한다.

결과에는 성공 여부, 지속 시간, 처치한 보스, 획득 부품, 보유 부품과 계속 버튼을 표시한다. 계속하면 출격 화면으로 돌아간다.

첫 정산 수치는 다음과 같다.

| 조건 | 부품 |
|---|---:|
| 3분 이상 참여 | 10 |
| 첫 유효 런 | 30 |
| 보스 1 처치 | 12 |
| 보스 2 처치 | 18 |
| 보스 3 처치 | 25 |
| 전장 클리어 | 30 |
| 보스별 최초 처치 | 각 20 |

첫 유효 런은 3분 이상 진행했거나 보스를 하나 이상 처치한 런이다. 따라서 최소 40부품을 얻고, 첫 추가 코어 가격 40으로 전도·부식·관성 중 하나를 선택 해금할 수 있다. 이후 코어 해금 가격은 100, 160이다.

부품과 가격은 `META_TUNING`에 둔다. 일반 적 처치 수는 부품에 직접 비례하지 않는다.

## 4. 구조와 데이터 흐름

### 4.1 전투

- `BossRewardDefinition`: 보상 ID, 조건과 표시 정보
- `BossBuild`: 보유 보상과 실제 전투 수치
- `SiegeBossManager`: 제3 보스 파츠, 이동과 공격 적용
- `bossAttackPatterns`: 조준탄, 확산탄, 낙하물과 이동 레이저 명세
- `EncounterDirector`: 다음 스테이지 존재 여부에 따른 보상 또는 완료 전환

```text
보스 1·2 처치
→ 다음 스테이지 존재
→ 적격 희귀 보상 3개 선택
→ 다음 스테이지

보스 3 처치
→ 다음 스테이지 없음
→ RunResult 생성
→ 결과 화면
```

### 4.2 저장과 메타

- `MetaProgress`: 부품, 해금 코어, 마지막 출격 구성, 최초 보상 claim
- `RunIdentity`: run ID, battlefield ID, threat ID, seed
- `RunResult`: 성공, 시간, 처치 보스, 시작 코어와 런 빌드
- `MetaStore`: versioned localStorage 읽기·쓰기
- `settleRun`: `RunResult`와 기존 claim을 입력받아 정산 결과를 반환하는 순수 함수

```text
결과 도착
→ run ID 중복 확인
→ 정산과 새 claim 계산
→ claim 포함 전체 MetaProgress 저장
→ 저장 성공 뒤 결과 화면 표시
```

저장 키는 하나만 사용한다. schema version은 1로 시작한다. JSON 파싱이나 검증에 실패하면 손상 원본을 별도 백업 키에 보존하고 기본값으로 복구한다. 구매 권한은 이번 범위에 없다.

## 5. 경계 조건

- 보유하지 않은 코어는 출격 슬롯에 넣을 수 없다.
- 시작 구성은 정확히 3개이며 같은 코어 중복을 허용한다.
- 잘못된 저장 구성은 반향 코어 3개로 복구한다.
- 부품은 음수가 될 수 없다.
- 같은 run ID는 두 번 정산하지 않는다.
- 코어 구매는 잔액과 잠금 상태를 함께 검증한다.
- 전투 중 새 해금은 현재 런에 영향을 주지 않는다.
- 보스 파츠가 파괴되면 collider와 담당 공격을 즉시 제거한다.
- 같은 레이저 활성 구간은 플레이어에게 무적 시간 안에서 중복 피해를 주지 않는다.
- 패배와 완료 중 예약된 보스 공격은 모두 취소한다.

## 6. 검증

### 6.1 단위 테스트

- 9종 보상 등록, 조건, 중복 제외와 seeded 선택
- 각 희귀 보상의 실제 수치와 비재귀 제한
- 다음 스테이지가 있을 때만 보상 정지
- 제3 보스 파츠 잠금, 자유 파괴와 코어 노출
- 공격 파츠 파괴에 따른 패턴 중단
- 레이저 예고·활성·정리
- 제3 구간 데이터 검증과 하강 속도 유지
- 참여, 최초, 보스와 클리어 부품 계산
- 중복 run ID 정산 방지
- 코어 가격 순서, 구매와 구성 복구
- 저장 round trip과 손상 데이터 복구

### 6.2 브라우저 테스트

- 보스 1·2에서 적격 보상 3개 선택 후 다음 구간 진행
- 제3 구간 진입과 제3 보스 네 공격
- 파츠 파괴 후 공격 중단과 코어 분노 단계
- 제3 보스 처치 후 보상 없이 결과 표시
- 패배 결과가 이미 처치한 보스 부품을 유지
- 첫 유효 런 뒤 새 코어 구매와 3슬롯 구성
- 새 구성으로 재출격
- 새로고침 뒤 부품, 해금과 구성 유지
- 데스크톱과 모바일 입력으로 전체 흐름 완료

브라우저 전체 검증은 세 구현 묶음이 합쳐진 뒤 한 번 실행한다. 각 묶음 안에서는 단위 테스트와 프로덕션 빌드를 우선한다.

## 7. 의도적 후속 범위

- 기록과 상점 탭
- 일반 능력 연구와 최대 등급 해금
- 영구 능력치와 외형
- 고정 위협도 1 이상
- 광고·결제 SDK
- 신규 일반 적
- 미술과 사운드

현재 데이터와 저장 구조는 이 항목을 추가할 수 있지만 빈 화면, 가짜 상품과 범용 플러그인 구조는 미리 만들지 않는다.
